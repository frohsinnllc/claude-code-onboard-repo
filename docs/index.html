# Onboard a repository

Goal: understand a repo well enough to make safe changes — without reading every file.

1. Shape.       README*, CLAUDE.md/AGENTS.md, package.json/pyproject/go.mod, /docs.
2. Entry points. main / server.* / index.* / CLI bin / routes. Trace one path end to end.
3. Map layers.   entry → handlers → logic → storage/external. Write a 5-line map.
4. Conventions.  Skim 3–4 files: naming, error handling, test style. Match them later.
5. Risks.        Fragile/critical paths (payments, auth, data writes) + TODO/FIXME/HACK.
6. Verify how.   Find the *smallest relevant gate* (test/build) for a typical change.

Output a brief: STACK / RUN-TEST-BUILD / ARCHITECTURE / CONVENTIONS / DO-NOT-TOUCH / GATE.
Then stop — do not change code during onboarding. The brief is the deliverable.
